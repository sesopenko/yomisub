# P18 — Publish the three artifacts recoverably

**Size:** 5. **Prerequisite:** P17.

## Work

- Finish and validate SRT, ASS and the evidence ZIP in destination-local staging. Publish using the planned sibling filenames. Serialize concurrent publications for the same stem and language.
- Under a per-destination lock, capture the previous presence and content of each file, including an SRT-only legacy install. Journal the replacements. Recovery before a durable commit marker restores that exact prior state, removing newly introduced files. Recovery after the marker keeps the new generation and finishes cleanup. A successful generation reports all three paths. Independent file readers may observe replacements in progress.

## Acceptance

- Inject failure at every replacement for empty, SRT-only and full prior sets. Simulate a crash on both sides of the commit marker, including after the third rename. Recover twice and compare file presence and bytes. Run two competing publications and verify the final three files come from one run.

- In a fresh process call the public publish operation with a pending journal from a previous failure. It must acquire the destination lock and recover the old journal before it snapshots any prior files. Interrupt this second publication too and check recovery restores the same pre-run set.
