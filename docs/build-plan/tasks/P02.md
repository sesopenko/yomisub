# P02 — Define application and adapter contracts

**Size:** 5. **Prerequisite:** P01.

## Work

- Define distinct generation and replay requests and results. Generation carries the selected media, stream, language, model and optional stem preference, and publishes three sibling paths. Replay reads an immutable input bundle, applies optional explicit corrections, and writes SRT and ASS in a specified output directory. Both results include review findings and diagnostics. P18 owns three-file generation publication.
- Define small application-owned protocols for track lookup and audio preparation, model execution targets, transcription, scanning, optional separation, language grouping, evidence storage, writers and publication. Define the pure planner boundary shared by generation and replay.
- Establish a fake-driven workflow and reusable behavioral contract tests before implementing production adapters. Specify which failures stop publication and how optional failures appear in the result.

## Acceptance

- Exercise a generation request and a replay with fakes. Assert replay calls the same planner and performs no inference. Inject a required scan failure and verify the publisher gets no call. Inject an optional failure and verify a diagnostic accompanies the preserved baseline.
- Check that the core imports and its contracts run without GTK, GPU libraries, or media binaries. Cross-reference the adapter tasks that will execute the relevant contracts.

- Give each unresolved editorial or diagnostic finding a stable ID. The generation result and GTK count equal the number of distinct open IDs in the published bundle, including optional-stage and format-loss findings. Corrected replay reports distinct open findings for its own exported result and leaves the bundle’s original findings intact. Link one finding to several screen states in a contract test and assert a count of one.
